# Cronopio 3D — cart-side maths (`cronopio3d.h`)

`sdk/include/cronopio3d.h` is a header-only floating-point 3D pipeline the
cart compiles in. It pairs with the host's triangle-submission syscalls
(`cron_polys`, `cron_zbuf`; see [syscalls.md](syscalls.md)): the cart
transforms, projects, lights and clips geometry, then submits screen-space
triangles for the host to rasterise.

It uses CronoVM's `f32` (single-instruction `FADD`/`FMUL`/`FDIV`/`FSQRT`),
the intended path for simple 3D. The retro look comes from the 8 bpp
framebuffer and affine texturing, not the maths precision.

## What's in it

- **Vectors** — `cron_vec3`, `cron_vec4`, plus `cron_v3_add/sub/scale/dot/
  cross/len/norm`.
- **Matrices** (`cron_mat4`, row-major, out-pointer API) — `identity`, `mul`,
  `translate`, `scale`, `rot_x/y/z`, `perspective`, `lookat`, `mat_point`.
- **Trig** — `cron_sin` / `cron_cos` (range-reduced degree-7 polynomial).
- **Pipeline** — `cron_emit_tri` transforms one source triangle by an MVP
  matrix, clips it against the near plane (`cron_clip_near`, Sutherland-
  Hodgman, yields 0/1/2 triangles), perspective-divides and maps to the
  320×240 viewport (`cron_to_screen`), producing `cron_vert_t`s ready for
  `cron_polys`.
- **Quads / culling** — `cron_quad` (4 verts → 2 triangles), `cron_facing`
  (2D winding test for back-face culling).
- **Lighting** — `cron_mat_dir` (transform a normal/light vector),
  `cron_tri_normal`, `cron_lambert` (diffuse term), `cron_palette_ramp`
  (build a dark→bright gradient) and `cron_shade` (intensity → ramp index).
  For Gouraud lighting on the indexed palette: build a ramp, set each
  `cron_cvert.light` to a ramp index from the per-vertex intensity, and draw
  `CRON_POLY_GOURAUD` — the interpolated index picks the gradient colour
  directly (no cmap needed). `examples/lit/` is a worked Gouraud-lit cube.

## Minimal frame

```c
#include <cronopio.h>
#include <cronopio3d.h>

volatile uint8_t *CRON_FB = 0; volatile uint32_t *CRON_PAL = 0;

static cron_mat4   mvp;
static cron_vert_t batch[6];
/* per-vertex {u, v, light}; only those fields are read by cron_emit_tri */
static const cron_cvert attr[3] = {
    {{0,0,0,0}, 0, 0, 16}, {{0,0,0,0}, 0, 0, 16}, {{0,0,0,0}, 0, 0, 16}
};

static float t;

static void frame(void) {
    cron_cls(0);

    cron_mat4 proj, view, model, mv;
    cron_mat_perspective(&proj, CRON_PI * 0.5f,
                         (float)CRON_SCREEN_W / (float)CRON_SCREEN_H, 0.1f, 100.0f);
    cron_mat_lookat(&view, cron_v3(0, 0, 4), cron_v3(0, 0, 0), cron_v3(0, 1, 0));
    cron_mat_rot_y(&model, t);
    cron_mat_mul(&mv, &view, &model);
    cron_mat_mul(&mvp, &proj, &mv);

    /* one spinning triangle */
    int n = cron_emit_tri(batch, &mvp,
        cron_v3(-1, -1, 0), cron_v3(1, -1, 0), cron_v3(0, 1, 0), attr);
    if (n) cron_polys(CRON_POLY_FLAT, batch, n, 16, -1);

    t += 0.03f;
}

int main(void) {
    cron_resolve_video();
    cron_set_frame(frame);
    return 0;
}
```

Build it like any cart (`cvm-cc -I sdk/include … cart.c`); `cvm-cc` adds the
CronoVM runtime include path so `cronopio3d.h`'s `#include "cvm_intrin.h"`
resolves.

## Notes & limits

- **Depth**: pass `CRON_POLY_ZTEST` and bind a buffer with `cron_zbuf` for a
  z-buffer; otherwise sort your triangles back-to-front (painter's).
- **Texturing**: `CRON_POLY_TEX` (affine) or `| CRON_POLY_PERSP`
  (perspective-correct). Fill `cron_cvert.u/v` in texels; `cron_to_screen`
  packs them as Q16.16 and carries clip-`w` for the perspective divide.
  Texcoords **wrap** (tile) by default; add `CRON_POLY_CLAMP` to clamp to the
  edge instead — needed for single-sheet skins (e.g. Quake alias models),
  whose edge texels would otherwise wrap to the opposite border.
- **Turbulence**: `CRON_POLY_TURB` (with `TEX`) warps texcoords per pixel for a
  water/lava ripple (Quake-style). Bind the animation with `cron_turb(phase,
  amp)` — `phase` advances the sine (period 128, drive it from your clock),
  `amp` is the texel amplitude. The warp still wraps, so the texture keeps
  tiling. See [syscalls.md](syscalls.md).
- **Lighting**: `CRON_POLY_GOURAUD` interpolates `cron_cvert.light` through
  the active `cron_cmap` (set a light ramp). Flat triangles use the `arg`
  colour directly. For **per-texel** lighting (Quake-style lightmaps) use
  `CRON_POLY_LIGHTMAP` with `CRON_POLY_TEX`: bind a small per-surface light
  grid with `cron_lightmap(ptr,w,h)` and a `levels*256` table with
  `cron_colormap(ptr,levels)`; fill `cron_vert_t.lu/.lv` (lightmap texels,
  perspective-correct alongside `.u/.v`), and each pixel becomes
  `colormap[lightgrid[lu,lv]*256 + texel]`. The light grid is sampled
  **bilinearly**, so coarse lumels gradate smoothly (like a software block
  light). See [syscalls.md](syscalls.md).
- **Keep frame functions modest.** Heavy helpers are `noinline` to respect
  the translator's per-function register budget; if a function still grows
  large, split it.
- The maths is `float`; if you want authentic fixed-point GTE-style
  precision instead, that's a separate header — ask.
